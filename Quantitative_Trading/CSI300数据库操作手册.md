# 沪深300历史成分与行情数据库操作手册

## 1. 文档目的

本文档说明如何理解、查询、校验和重建当前沪深300历史成分与行情数据库。目标读者包括量化研究人员、回测开发人员和后续数据维护人员。

数据库解决的核心问题是：给定覆盖范围内的历史交易日，查询按中证指数半年定期调整公告校正后的沪深300成分股，并关联原始行情、前复权行情、成交状态和数据质量信息，避免直接用当前300只成分股回溯历史造成幸存者偏差。当前版本已完成2019年12月至2026年6月共14次半年定期调整的人工官方核验；临时调整日期未纳入，因此不能称为官方逐日完整成分库。

## 4. 数据来源与口径

### 4.1 行情

- 数据源：Baostock；
- 原始价格：`adjustflag="3"`；
- 前复权价格：`adjustflag="2"`；
- 成交量单位：股；
- 成交额单位：人民币元；
- 停牌状态：Baostock `tradestatus`；
- 缺失价格不使用 `ffill`、`bfill` 或0值替换。

原始价格用于成交模拟、滑点、止损、涨跌停和成交均价分析。前复权价格用于收益率、动量、均线和其他时间序列指标。成交额和成交量不能与前复权价格混合计算VWAP。

前复权历史价格会随着后续分红、送转和供应商数据修订而重写。同一历史日期在不同下载时间可能得到不同绝对前复权价格。当前归档保存了构建时的前复权结果和构建清单，但没有独立调整因子表，也没有逐文件校验和。需要严格复现实验时，应冻结原始CSV、记录抓取时间和依赖版本，并在后续版本增加调整因子、供应商版本和输入文件SHA-256清单。

### 4.2 历史成分股

历史成分采用双来源重建：Baostock `query_hs300_stocks(date)` 提供每期完整300股集合，`CSI300_remake_report.xlsx` 提供从中证指数官网人工整理并由项目所有者确认可靠的半年定期调入、调出和实施日期。14次官方事件共247组调入调出，与Baostock相邻快照的代码变化全部精确一致。

Excel第五列使用统一标题 `生效日期（当天收市后生效）`，但文件跨越了规则切换期，脚本不能把括号说明机械地追溯应用到所有年份。当前工作簿中2020年的两期日期值是旧规则下“6月或12月第二个星期五后的首个交易日启用新样本”的正式生效交易日，因此直接作为 `valid_from`；例如2020-06-15映射为2020-06-15。2021年起，日期值是第二个星期五收市后实施日期，数据库把下一个交易日写入 `effective_date` 和 `valid_from`；例如2021-06-11收市后调整，因端午节假期，下一个交易日为2021-06-15。

2019-12-16事件是基准快照例外，不直接作为 `valid_from`。它用于核对2020年初始股票池：其16只调入股全部存在于最早Baostock完整快照，16只调出股全部不在该快照。由于没有2019-12-16的完整300股集合，且数据库行情从2020年开始，最早完整快照日期2019-12-30作为基准 `valid_from`，不会影响2020-01-02以后的查询。

Baostock原始18期快照保存在 `baostock_membership_snapshots_raw`，其日期只表示首次观测日期。正式 `membership_snapshots` 使用14期官方定期调整日期。当前来源标记为：

```text
baostock_baseline_official_change_cross_checked
csindex_official_regular_manual_reconstruction
```

临时调整公告未收集，因此临时变化的精确日期不进入正式股票池。下一次半年定期调整时，使用经Excel调入调出集合精确校验过的完整300股快照，使每个半年边界的股票池保持正确。该口径显著降低幸存者偏差，但仍需披露“临时调整日期省略”这一限制。

当前免费数据没有历史调仓权重，因此 `weight` 为 `NULL`。数据库不会伪造每日权重。

## 6. SQLite表和视图

### 6.1 `security`

证券主表，每只历史成分股一行。

| 字段 | 类型 | 说明 |
|---|---|---|
| `stock_code` | TEXT | 六位股票代码，主键 |
| `name` | TEXT | 当前归档名称 |
| `exchange` | TEXT | `SH`或`SZ` |
| `first_seen` | TEXT | 行情最早日期 |
| `last_seen` | TEXT | 行情最晚日期 |

股票代码必须按文本处理，不能转成整数，否则会丢失前导零。

### 6.2 `trading_calendar`

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | TEXT | `YYYY-MM-DD`，主键 |
| `is_trading_day` | INTEGER | 1表示交易日 |

SQLite中日期以ISO文本保存。`YYYY-MM-DD`格式可以直接安全排序和比较。

### 6.3 `daily_price_raw`

不复权日行情，主键为 `(date, stock_code)`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | TEXT | 交易日期 |
| `stock_code` | TEXT | 六位股票代码 |
| `open_raw` | REAL | 不复权开盘价 |
| `high_raw` | REAL | 不复权最高价 |
| `low_raw` | REAL | 不复权最低价 |
| `close_raw` | REAL | 不复权收盘价 |
| `volume_shares` | INTEGER | 成交量，股 |
| `amount_cny` | REAL | 成交额，元 |
| `trade_status` | INTEGER | 1正常交易，0停牌或不可交易 |
| `price_source` | TEXT | 行情来源 |

### 6.4 `daily_price_adjusted`

前复权日行情，主键为 `(date, stock_code)`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | TEXT | 交易日期，与`stock_code`构成主键 |
| `stock_code` | TEXT | 六位股票代码，与`date`构成主键 |
| `open_adj` | REAL | 前复权开盘价 |
| `high_adj` | REAL | 前复权最高价 |
| `low_adj` | REAL | 前复权最低价 |
| `close_adj` | REAL | 前复权收盘价 |
| `adjustment_source` | TEXT | 复权来源 |

### 6.5 `components_snapshot`

记录数据下载时的当前沪深300成分股。它只表示当前快照，不能用于历史回测。

| 字段 | 类型 | 说明 |
|---|---|---|
| `snapshot_date` | TEXT | 当前成分抓取日期，联合主键 |
| `index_code` | TEXT | 指数代码，联合主键 |
| `stock_code` | TEXT | 股票代码，联合主键 |
| `name` | TEXT | 快照中的股票名称 |
| `source` | TEXT | 快照来源 |

### 6.6 `membership_snapshots`

每个官方半年定期调整可用交易日的完整300股快照。当前共14期，每期严格300只。`effective_date` 是回测可以开始使用新股票池的首个交易日，不是公告发布日期，也不是Baostock首次观测日期。

| 字段 | 说明 |
|---|---|
| `index_code` | 指数代码，当前为`000300` |
| `effective_date` | 成分集合生效日期 |
| `stock_code` | 成分股代码 |
| `weight` | 调仓权重，当前为空 |
| `announcement_date` | 公告日期，当前为空 |
| `source` | 快照来源 |
| `source_url` | 来源地址 |

### 6.6.1 `official_adjustments`

保存Excel中的247组官方调入调出及其日期映射，是成分重建的审计证据。

| 字段 | 说明 |
|---|---|
| `official_event_date` | Excel记录的官方实施日期 |
| `valid_from` | 新股票池首个可用交易日 |
| `out_code`、`out_name` | 调出股票 |
| `in_code`、`in_name` | 调入股票 |
| `matched_observed_date` | 与本次代码变化完全一致的Baostock快照日期 |
| `source_file` | 官方人工整理Excel文件名 |
| `source_sha256` | 输入Excel的SHA-256 |
| `verification_status` | 当前为`user_verified_official` |

### 6.6.2 `baostock_membership_snapshots_raw`

保存更新前的18期、5,400行Baostock原始快照。`observed_date` 仅表示Baostock首次观测到该完整集合的日期。该表用于审计和重新匹配，不作为正式回测股票池。

### 6.7 `universe_membership`

从快照推导出的成分有效区间，是解决幸存者偏差的核心表。

成员资格使用半开区间：

```text
valid_from <= date < valid_to
```

`valid_to` 是首个不再属于指数的日期。仍在指数中的记录使用 `9999-12-31`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `index_code` | TEXT | 指数代码，联合主键 |
| `stock_code` | TEXT | 股票代码，联合主键 |
| `valid_from` | TEXT | 官方定期调整后新股票池首个可用交易日，联合主键 |
| `valid_to` | TEXT | 半开区间终点 |
| `weight` | REAL/NULL | 入段权重，当前为空 |
| `weight_date` | TEXT/NULL | 权重对应日期 |
| `source` | TEXT | 区间推导来源 |

### 6.8 `membership_weights` 和 `membership_weight_intervals`

用于保存调仓时点权重及其有效区间。当前免费数据没有权重，因此表结构已准备好，但 `weight` 为空。

`membership_weights` 保存每个快照日的权重观测，主键是 `(index_code, effective_date, stock_code)`。`membership_weight_intervals` 将权重观测转换为 `[valid_from, valid_to)` 区间。即使未来补入权重，它也只代表最近一次调仓快照权重，不能解释为每日真实指数权重。

### 6.9 `data_quality_issues`

所有不能静默忽略的问题都写入此表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `issue_id` | INTEGER | 自增主键 |
| `table_name` | TEXT | 问题所属表或视图 |
| `issue_date` | TEXT/NULL | 问题日期 |
| `stock_code` | TEXT/NULL | 涉及股票 |
| `issue_type` | TEXT | 稳定的问题类型 |
| `severity` | TEXT | `blocker`或`warning` |
| `details` | TEXT | 详细说明或JSON |

| `severity` | 含义 |
|---|---|
| `blocker` | 阻止正式使用，例如整只历史成分股没有行情 |
| `warning` | 保留数据但需要知晓或人工核查 |

### 6.10 `metadata`

保存数据根目录、行情行数、成分来源和官方核验状态等构建元数据。

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | TEXT | 元数据键，主键 |
| `value` | TEXT | 元数据值；布尔值也以文本保存 |

### 6.11 `daily_universe` 视图

回测首选入口。它按交易日连接：

- `trading_calendar`；
- `universe_membership`；
- 原始行情；
- 前复权行情；
- 最近一次有效的调仓快照权重；当前全部为空。

当前版本中，每个覆盖范围内的交易日严格返回300行。停牌或退市后无源行情的股票仍保留成员身份，但 `is_tradeable=0`，价格可以为 `NULL`。因为临时调整日期被省略，当前133个无行情成员日集中在 `600837` 和 `601989`，分别持续到下一次半年定期调整。

视图主要字段：

| 字段 | 可空 | 说明 |
|---|---|---|
| `date` | 否 | 交易日 |
| `index_code` | 否 | 指数代码 |
| `stock_code` | 否 | 当日成员代码 |
| `weight` | 是 | 最近调仓快照权重，不是每日权重 |
| `weight_date` | 是 | 最近权重快照日期 |
| `open_raw`至`close_raw` | 是 | 原始OHLC |
| `open_adj`至`close_adj` | 是 | 前复权OHLC |
| `volume_shares` | 是 | 成交股数 |
| `amount_cny` | 是 | 成交额 |
| `trade_status` | 是 | 源行情交易状态；无源行情时为空 |
| `is_tradeable` | 否 | 派生可交易标志 |
| `price_source` | 是 | 原始行情来源 |
| `adjustment_source` | 是 | 复权行情来源 |

`is_tradeable` 的精确公式为：

```text
trade_status = 1
AND volume_shares > 0
AND amount_cny > 0
```

任一条件不满足，或该成员日没有源行情行时，`is_tradeable=0`。不可交易可能表示停牌、零成交、退市前无行情或数据源缺失；当前视图没有单独的 `untradeable_reason` 字段，需要按下列SQL进一步分类。

| 对象 | 主键或唯一键 |
|---|---|
| `security` | `stock_code` |
| `trading_calendar` | `date` |

| `data_quality_issues` | `issue_id` |
| `metadata` | `key` |

当前schema没有声明跨表外键，跨表一致性由构建器、复合主键和校验器保证。因此 `PRAGMA foreign_key_check` 只能检查未来新增的外键，不能替代 `validate_csi300_sqlite.py`。

在DataGrip或Query Console中查看任意对象的实际DDL：

```sql
SELECT type, name, sql
FROM sqlite_master
WHERE name = 'daily_universe';
```

查看字段类型、可空性和主键顺序：

```sql
PRAGMA table_info('daily_price_raw');
```

实际数据库DDL是最终技术事实；本文数据字典用于解释业务语义。

## 8. 快速连接数据库

### 8.1 使用DataGrip连接（推荐）

连接步骤：

1. 打开DataGrip；
2. 选择 `File` → `New` → `Data Source` → `SQLite`；
3. 在 `File` 或数据库文件位置中选择：

   ```text
   D:\Desktop\NotProjext\Quantitative_Trading\data_v5\csi300_2020_present.sqlite
   ```

4. 如果DataGrip提示缺少SQLite驱动，点击 `Download missing driver files`；

### 9.10 计算前复权日收益率

```sql
WITH calendar_order AS (
    SELECT
        date,
        LAG(date) OVER (ORDER BY date) AS previous_market_date
    FROM trading_calendar
    WHERE is_trading_day = 1
),
prices AS (
    SELECT
        date,
        stock_code,
        close_adj,
        LAG(close_adj) OVER (
            PARTITION BY stock_code
            ORDER BY date
        ) AS previous_close_adj,
        LAG(date) OVER (
            PARTITION BY stock_code
            ORDER BY date
        ) AS previous_price_date
    FROM daily_price_adjusted
),
daily_returns AS (
    SELECT
        p.date,
        p.stock_code,
        p.close_adj,
        CASE
            WHEN p.previous_price_date = c.previous_market_date
            THEN p.close_adj / p.previous_close_adj - 1.0
            ELSE NULL
        END AS daily_return
    FROM prices AS p
    JOIN calendar_order AS c ON c.date = p.date
)
SELECT
    u.date,
    u.stock_code,
    r.close_adj,
    r.daily_return
FROM daily_universe AS u
LEFT JOIN daily_returns AS r
  ON r.date = u.date
 AND r.stock_code = u.stock_code
ORDER BY u.date, u.stock_code;
```

收益率先在完整 `daily_price_adjusted` 上计算，再连接当日股票池。只有上一价格日期等于市场前一交易日时才输出日收益率；停牌、缺行情或股票离池后重新入池不会被误算成单日收益。不要用 `close_raw` 直接跨除权日计算收益率。

### 9.11 计算20个有效观测的移动平均

```sql
WITH windows AS (
    SELECT
        date,
        stock_code,
        close_adj,
        COUNT(close_adj) OVER (
            PARTITION BY stock_code
            ORDER BY date
            ROWS BETWEEN 19 PRECEDING AND CURRENT ROW
        ) AS observation_count,
        AVG(close_adj) OVER (
            PARTITION BY stock_code
            ORDER BY date
            ROWS BETWEEN 19 PRECEDING AND CURRENT ROW
        ) AS average_close
    FROM daily_price_adjusted
)
SELECT
    date,
    stock_code,
    close_adj,
    CASE WHEN observation_count = 20 THEN average_close END AS ma20
FROM windows
ORDER BY stock_code, date;
```

该查询要求20个非空价格观测后才输出 `ma20`。如果策略严格要求连续20个市场交易日，还需要像第9.10节一样比较窗口内价格日期与 `trading_calendar`，缺失任何交易日时将指标设为 `NULL`。

### 9.12 正确的指标预热方式

```sql
WITH windows AS (
    SELECT
        date,
        stock_code,
        close_adj,
        COUNT(close_adj) OVER (
            PARTITION BY stock_code
            ORDER BY date
            ROWS BETWEEN 19 PRECEDING AND CURRENT ROW
        ) AS observation_count,
        AVG(close_adj) OVER (
            PARTITION BY stock_code
            ORDER BY date
            ROWS BETWEEN 19 PRECEDING AND CURRENT ROW
        ) AS average_close
    FROM daily_price_adjusted
),
indicators AS (
    SELECT
        date,
        stock_code,
        close_adj,
        CASE WHEN observation_count = 20 THEN average_close END AS ma20
    FROM windows
)
SELECT
    u.date,
    u.stock_code,
    u.is_tradeable,
    i.close_adj,
    i.ma20
FROM daily_universe AS u
LEFT JOIN indicators AS i
  ON i.date = u.date
 AND i.stock_code = u.stock_code
WHERE u.date = '2023-12-11'
ORDER BY u.stock_code;
```

这是更推荐的回测模式：先用完整个股历史计算指标，再用当日历史股票池过滤。

## 10. 回测使用规则

### 10.1 推荐数据路径

1. 从 `daily_price_adjusted` 计算指标和收益率；
2. 用 `daily_universe` 过滤当前版本推导的当日成分股；
3. 用 `is_tradeable` 判断能否成交；
4. 用原始OHLC模拟开盘、收盘、止损和滑点；
5. 用 `data_quality_issues` 排除阻断问题或记录研究限制。

### 10.2 防止未来函数

- 不使用未来日期的成分股名单；
- 不使用 `bfill`；
- 不把停牌日价格当成可成交价格；
- 调仓信号和实际成交时间必须在回测规则中明确；
- 官方公告日期与生效日期不应混用；
- 使用调仓后生效名单时，成交时间至少应满足策略的信息可用性约束。

### 10.3 成交额和成交量

成交均价应基于不复权口径：

```sql
SELECT
    date,
    stock_code,
    amount_cny / volume_shares AS raw_vwap,
    low_raw,
    high_raw
FROM daily_price_raw
WHERE volume_shares > 0
  AND amount_cny > 0;
```

不要使用 `amount_cny / volume_shares` 与 `close_adj` 比较。

第三步，补齐所有历史成分股行情：

```powershell
python download_membership_prices.py --root data_v5 --membership data_v5/membership_snapshots.csv --start-date 2020-01-01 --end-date 2026-08-05 --delay 0.1
```

脚本按股票代码跳过已有文件，支持断点续传，但“存在文件”不等于“文件有效”。下载完成后必须运行CSV校验器。检查：

```text
data_v5/historical_price_manifest.json
```

必须满足：

```text
covered_after_run = 493
missing_after_run = []
```

股票总数可能随时间变化，不应在代码中永久写死493。

第四步，完整执行第12.1节的五个动作一次：CSV校验、合并CSV、使用原始Baostock快照建库、应用官方成分更新器、SQLite校验。不能跳过官方成分更新器，也不需要重复运行两次。

### 12.3 覆盖、续传和失败规则

- `csi300_download_v5.py --overwrite` 会重新下载当前成分股文件；
- `download_membership_prices.py` 按代码跳过已存在历史文件；
- 网络任务中断后可以重复运行，原子写入可避免半截CSV；
- manifest中的失败项必须为0，或在质量报告中有明确阻断记录；
- 不能通过删除membership中的缺失股票来让校验通过；
- DataGrip必须断开正式SQLite连接，避免Windows文件锁阻止原子替换；
- 正式构建前应备份CSV、快照、官方公告证据和旧SQLite。

### 12.4 当前可重复性的边界

现有脚本能够从固定CSV确定性重建SQLite，但从网络重下载不保证逐字节一致，原因包括供应商历史修订、前复权重算、成分接口更新和依赖版本变化。正式版本还应增加：

- `requirements.txt` 依赖锁；
- 每个输入文件的SHA-256；
- 官方公告原件及其校验和；
- 调整因子和抓取时间；
- 数据版本号和 `as_of_date`。

## 13. 官方公告核验流程

当前官方输入为项目所有者从中证指数官网人工整理并确认可靠的 `CSI300_remake_report.xlsx`，覆盖2019年12月至2026年6月的14次半年定期调整，共247组调入调出。该文件只覆盖定期调整，不覆盖临时调整。

`apply_official_membership.py` 执行以下校验：

1. 检查Excel五个核心字段、代码格式、空值和重复项；
2. 检查每期调入数等于调出数；
3. 将每期调入调出集合与Baostock相邻完整快照做精确集合匹配；
4. 2019年至2020年使用表内已经表示“第二个星期五后首个交易日”的正式生效日期；
5. 2021年起将收市后实施日期映射到下一个交易日；
6. 取匹配后的完整300股集合生成14期正式快照；
7. 保留18期原始Baostock快照和Excel SHA-256；
8. 重建成员有效区间并确认每天严格300只；
9. 在全部检查通过后提交事务，否则回滚；
10. 生成修正前后差异报告和数据库备份。

当前元数据口径：

```text
membership_officially_verified = True
membership_scope = official_regular_adjustments_only
temporary_adjustments_included = False
membership_valid_from_semantics = first_trading_day_new_pool_is_usable
```

这里的“官方核验”仅指半年定期调整。研究报告不能省略 `temporary_adjustments_included=False`。如果未来补齐临时公告，应在新的数据版本中导入临时事件并重新生成区间，不能直接删除现有审计记录。

## 14. 质量警告说明

当前140条警告包括：

| 类型 | 数量 | 处理方式 |
|---|---:|---|
| `vwap_outside_ohlc` | 5 | 保留原始值，必要时用第二数据源核查 |
| `member_price_missing` | 133 | 临时调整日期省略导致，仅涉及`600837`和`601989`；保留成员行但不可交易 |
| `temporary_adjustments_omitted` | 1 | 研究结论披露仅覆盖半年定期调整 |
| `weights_missing` | 1 | 不运行依赖历史指数权重的策略 |

质量警告不等于可以忽略。研究报告中应披露与策略相关的警告。

## 17. 常见问题

### 17.1 为什么不是每天直接存一个300股CSV？

规范化存储可以避免重复行情，保留成分区间和原始来源，并通过 `daily_universe` 视图随时生成每日300股结果。

### 17.2 当前300只股票还有用吗？

有用。它们是493只历史成分股全集的一部分，也用于核对最新快照。但不能单独回溯到2020年。

### 17.3 为什么停牌股票仍出现在 `daily_universe`？

成员身份和可交易状态是不同概念。停牌股票仍属于指数，但不能成交。

### 17.4 为什么不填补133个缺价成员日？

填补估值价格不等于存在可成交价格。当前数据库保留 `NULL` 并设置 `is_tradeable=0`。这133行仅涉及临时调整日期未纳入正式区间的`600837`和`601989`，避免制造虚假成交。

### 17.5 为什么权重全是空？

免费Baostock历史成分快照不提供调仓权重。必须从中证公告、Tushare Pro、Wind或其他专业来源补充。

### 17.6 可以直接用于正式研究吗？

可以用于半年定期调整口径的研究和回测开发。它不是包含临时调整的官方逐日完整成分库；发表或资金决策前必须披露临时调整省略，并根据策略决定是否需要历史权重、调整因子和第二行情源复核。

### 17.7 数据库可以直接修改吗？

不推荐。正式库应由原始快照、官方Excel和 `apply_official_membership.py` 重建。手工修改数据库会破坏可追溯性，除非同时记录修改来源并更新构建流程。

## 18. 最终验收清单

每次正式使用前确认：

- `PRAGMA integrity_check` 返回 `ok`；
- `database_quality_report.json` 的 `errors` 为空；
- `security` 为493只，或与最新构建清单一致；
- 原始和复权行情行数相等；
- `daily_universe` 每个交易日均为300行；
- `historical_price_manifest.json` 的 `missing_after_run` 为空；
- 没有 `blocker` 级质量问题；
- 策略已正确区分原始价格和前复权价格；
- 策略只在 `is_tradeable=1` 时成交；
- 研究结论披露“仅半年定期调整、临时调整日期省略”和权重限制；当前应检查 `temporary_adjustments_omitted` 警告。

完成以上检查后，`daily_universe` 可以作为半年定期调整口径下、避免“仅用当前成分股回溯”这一直接幸存者偏差的日频回测入口。若需要官方逐日完整股票池，仍需补齐临时调整公告。
