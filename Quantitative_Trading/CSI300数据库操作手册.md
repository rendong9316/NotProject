# 沪深300历史成分与行情数据库操作手册

## 1. 文档目的

本文档说明如何理解、查询、校验和重建当前沪深300历史成分与行情数据库。目标读者包括量化研究人员、回测开发人员和后续数据维护人员。

数据库解决的核心问题是：给定覆盖范围内的历史交易日，查询按中证指数半年定期调整公告校正后的沪深300成分股，并关联原始行情、前复权行情、成交状态、公司行为和数据质量信息，避免直接用当前300只成分股回溯历史造成幸存者偏差，同时避免不复权价格在除权日形成虚假账户损益。当前版本已完成2019年12月至2026年6月共14次半年定期调整的人工官方核验；临时调整日期未纳入，因此不能称为官方逐日完整成分库。

## 4. 数据来源与口径

### 4.1 行情

- 数据源：Baostock；
- 原始价格：`adjustflag="3"`；
- 前复权价格：`adjustflag="2"`；
- 成交量单位：股；
- 成交额单位：人民币元；
- 停牌状态：Baostock `tradestatus`；
- 缺失价格不使用 `ffill`、`bfill` 或0值替换。

原始价格用于成交模拟、滑点、止损、涨跌停和成交均价分析。前复权价格用于收益率、动量、均线和其他时间序列指标。成交额和成交量不能与前复权价格混合计算VWAP。

前复权历史价格会随着后续分红、送转和供应商数据修订而重写。同一历史日期在不同下载时间可能得到不同绝对前复权价格。当前版本已经从冻结的原始价和前复权价推导 `adjustment_factor_events`，并保存公司行为抓取时间；`data_v5/corporate_actions/manifest.json`记录4个公司行为CSV的行数和SHA-256，离线导入时自动验签。其他行情输入文件尚无完整逐文件校验和。需要严格复现实验时，应冻结原始CSV和 `data_v5/corporate_actions/`，记录依赖版本，并补充供应商版本和其他输入文件SHA-256清单。

### 4.2 历史成分股

历史成分采用双来源重建：Baostock `query_hs300_stocks(date)` 提供每期完整300股集合，`CSI300_remake_report.xlsx` 提供从中证指数官网人工整理并由项目所有者确认可靠的半年定期调入、调出和实施日期。14次官方事件共247组调入调出，与Baostock相邻快照的代码变化全部精确一致。

Excel第五列使用统一标题 `生效日期（当天收市后生效）`，但文件跨越了规则切换期，脚本不能把括号说明机械地追溯应用到所有年份。当前工作簿中2020年的两期日期值是旧规则下“6月或12月第二个星期五后的首个交易日启用新样本”的正式生效交易日，因此直接作为 `valid_from`；例如2020-06-15映射为2020-06-15。2021年起，日期值是第二个星期五收市后实施日期，数据库把下一个交易日写入 `effective_date` 和 `valid_from`；例如2021-06-11收市后调整，因端午节假期，下一个交易日为2021-06-15。

2019-12-16事件是基准快照例外，不直接作为 `valid_from`。它用于核对2020年初始股票池：其16只调入股全部存在于最早Baostock完整快照，16只调出股全部不在该快照。由于没有2019-12-16的完整300股集合，且数据库行情从2020年开始，最早完整快照日期2019-12-30作为基准 `valid_from`，不会影响2020-01-02以后的查询。

Baostock原始20期观测快照保存在 `baostock_membership_snapshots_raw`，其日期只表示首次观测日期。正式 `membership_snapshots` 使用14期官方定期调整日期。当前来源标记为：

```text
baostock_baseline_official_change_cross_checked
csindex_official_regular_manual_reconstruction
```

临时调整公告未收集，因此临时变化的精确日期不进入正式股票池。下一次半年定期调整时，使用经Excel调入调出集合精确校验过的完整300股快照，使每个半年边界的股票池保持正确。该口径显著降低幸存者偏差，但仍需披露“临时调整日期省略”这一限制。

当前免费数据没有历史调仓权重，因此 `weight` 为 `NULL`。数据库不会伪造每日权重。

### 4.3 公司行为

- 经济条款主源：巨潮资讯实施方案，经AkShare `stock_dividend_cninfo`读取；
- 旧代码和已合并证券补源：Baostock `query_dividend_data`；
- 独立核验：本地Baostock不复权与前复权价格之比；
- 现金口径：每股税前现金分红；
- 股份口径：送股和资本公积转增；
- 特殊事件：无法由普通分红解释时使用本地复权因子兜底。

公司行为处理在回测时只读SQLite，不临时访问公司行为接口。若沪深300基准CSV缺失或日期不足，研究入口仍会联网下载基准；要求完全离线时必须同时归档 `data_v5/benchmarks/csi300_daily.csv`。巨潮与Baostock均属于免费接口，不能替代交易所交收流水；`review`和`factor_only`状态必须随研究结果披露。

### 4.4 历史ST状态

`build_security_status.py`使用Baostock日线 `isST` 字段下载493只历史证券的每日ST状态，同时重新读取 `tradestatus` 与原始行情逐行核对。当前状态表与761,812条原始行情在 `(date, stock_code)` 上完全一致，交易状态冲突为0，ST标记为1的记录共5,385行。因子选股在信号日排除ST股票；已持仓后来变为ST时继续估值，并按约5%涨跌停判断能否卖出。

### 4.5 跨代码结算事件

`security_transitions`处理退市源证券换成另一证券代码的实际交收，当前两笔均来自上交所正式实施公告和新增股份上市结果公告：

| 源证券 | 目标证券 | 换股登记日 | 目标股份上市日 | 比例 |
|---|---|---|---|---:|
| `600837`海通证券 | `601211`国泰海通 | 2025-03-03 | 2025-03-17 | 0.62 |
| `601989`中国重工 | `600150`中国船舶 | 2025-09-04 | 2025-09-16 | 0.1339 |

正式公告规定零碎股由登记结算系统按小数尾数排序，同尾数时随机分配。回测无法访问全体股东排序，采用就近整数近似并记录理论股数与实际模拟股数的差异。该近似最多相差一股，不收取佣金、印花税或滑点。源证券停止行情后可以等待已核验的未来结算日；若持仓没有对应事件，回测立即阻断。

## 6. SQLite表和视图

### 6.1 `security`

证券主表，每只历史成分股一行。

| 字段 | 类型 | 说明 |
|---|---|---|
| `stock_code` | TEXT | 六位股票代码，主键 |
| `name` | TEXT | 当前归档名称 |
| `exchange` | TEXT | `SH`或`SZ` |
| `first_seen` | TEXT | 行情最早日期 |
| `last_seen` | TEXT | 行情最晚日期 |

股票代码必须按文本处理，不能转成整数，否则会丢失前导零。

### 6.2 `trading_calendar`

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | TEXT | `YYYY-MM-DD`，主键 |
| `is_trading_day` | INTEGER | 1表示交易日 |

SQLite中日期以ISO文本保存。`YYYY-MM-DD`格式可以直接安全排序和比较。

### 6.3 `daily_price_raw`

不复权日行情，主键为 `(date, stock_code)`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | TEXT | 交易日期 |
| `stock_code` | TEXT | 六位股票代码 |
| `open_raw` | REAL | 不复权开盘价 |
| `high_raw` | REAL | 不复权最高价 |
| `low_raw` | REAL | 不复权最低价 |
| `close_raw` | REAL | 不复权收盘价 |
| `volume_shares` | INTEGER | 成交量，股 |
| `amount_cny` | REAL | 成交额，元 |
| `trade_status` | INTEGER | 1正常交易，0停牌或不可交易 |
| `price_source` | TEXT | 行情来源 |

### 6.4 `daily_price_adjusted`

前复权日行情，主键为 `(date, stock_code)`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `date` | TEXT | 交易日期，与`stock_code`构成主键 |
| `stock_code` | TEXT | 六位股票代码，与`date`构成主键 |
| `open_adj` | REAL | 前复权开盘价 |
| `high_adj` | REAL | 前复权最高价 |

### 6.5 `components_snapshot`

记录数据下载时的当前沪深300成分股。它只表示当前快照，不能用于历史回测。

| 字段 | 类型 | 说明 |
|---|---|---|
| `snapshot_date` | TEXT | 当前成分抓取日期，联合主键 |
| `index_code` | TEXT | 指数代码，联合主键 |
| `stock_code` | TEXT | 股票代码，联合主键 |
| `name` | TEXT | 快照中的股票名称 |
| `source` | TEXT | 快照来源 |

### 6.6 `membership_snapshots`

每个官方半年定期调整可用交易日的完整300股快照。当前共14期，每期严格300只。`effective_date` 是回测可以开始使用新股票池的首个交易日，不是公告发布日期，也不是Baostock首次观测日期。

| 字段 | 说明 |
|---|---|
| `index_code` | 指数代码，当前为`000300` |
| `effective_date` | 成分集合生效日期 |
| `stock_code` | 成分股代码 |
| `weight` | 调仓权重，当前为空 |
| `announcement_date` | 公告日期，当前为空 |
| `source` | 快照来源 |
| `source_url` | 来源地址 |

### 6.6.1 `official_adjustments`

保存Excel中的247组官方调入调出及其日期映射，是成分重建的审计证据。

| 字段 | 说明 |
|---|---|
| `official_event_date` | Excel记录的官方实施日期 |
| `valid_from` | 新股票池首个可用交易日 |
| `out_code`、`out_name` | 调出股票 |
| `in_code`、`in_name` | 调入股票 |
| `matched_observed_date` | 与本次代码变化完全一致的Baostock快照日期 |
| `source_file` | 官方人工整理Excel文件名 |
| `source_sha256` | 输入Excel的SHA-256 |
| `verification_status` | 当前为`user_verified_official` |

### 6.6.2 `baostock_membership_snapshots_raw`

保存20期、6,000行Baostock原始观测快照。`observed_date` 仅表示Baostock首次观测到该完整集合的日期。该表用于审计和重新匹配，不作为正式回测股票池。

### 6.7 `universe_membership`

从快照推导出的成分有效区间，是解决幸存者偏差的核心表。

成员资格使用半开区间：

```text
valid_from <= date < valid_to
```

`valid_to` 是首个不再属于指数的日期。仍在指数中的记录使用 `9999-12-31`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `index_code` | TEXT | 指数代码，联合主键 |
| `stock_code` | TEXT | 股票代码，联合主键 |
| `valid_from` | TEXT | 官方定期调整后新股票池首个可用交易日，联合主键 |
| `valid_to` | TEXT | 半开区间终点 |
| `weight` | REAL/NULL | 入段权重，当前为空 |
| `weight_date` | TEXT/NULL | 权重对应日期 |
| `source` | TEXT | 区间推导来源 |

### 6.8 `membership_weights` 和 `membership_weight_intervals`

用于保存调仓时点权重及其有效区间。当前免费数据没有权重，因此表结构已准备好，但 `weight` 为空。

`membership_weights` 保存每个快照日的权重观测，主键是 `(index_code, effective_date, stock_code)`。`membership_weight_intervals` 将权重观测转换为 `[valid_from, valid_to)` 区间。即使未来补入权重，它也只代表最近一次调仓快照权重，不能解释为每日真实指数权重。

### 6.9 `data_quality_issues`

所有不能静默忽略的问题都写入此表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `issue_id` | INTEGER | 自增主键 |
| `table_name` | TEXT | 问题所属表或视图 |
| `issue_date` | TEXT/NULL | 问题日期 |
| `stock_code` | TEXT/NULL | 涉及股票 |
| `issue_type` | TEXT | 稳定的问题类型 |
| `severity` | TEXT | `blocker`或`warning` |
| `details` | TEXT | 详细说明或JSON |

| `severity` | 含义 |
|---|---|
| `blocker` | 阻止正式使用，例如整只历史成分股没有行情 |
| `warning` | 保留数据但需要知晓或人工核查 |

### 6.10 `metadata`

保存数据根目录、行情行数、成分来源和官方核验状态等构建元数据。

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` | TEXT | 元数据键，主键 |
| `value` | TEXT | 元数据值；布尔值也以文本保存 |

### 6.10.1 公司行为表和视图

`corporate_actions`保存公告原始经济条款，主键为 `(stock_code, ex_date, action_sequence)`。同一证券同一除权日可能同时存在年度分红和特别分红，因此不能只用证券与日期作为主键。

| 核心字段 | 说明 |
|---|---|
| `cash_dividend_gross_per_10` | 每10股税前现金分红 |
| `stock_dividend_per_10` | 每10股送股数量 |
| `transfer_per_10` | 每10股资本公积转增数量 |
| `record_date`、`ex_date`、`payment_date` | 登记、除权和派息日期 |
| `source` | `cninfo_via_akshare`或Baostock失败补源 |

`corporate_action_daily`按证券和除权日聚合多条公告，输出每股税前现金和股数乘数。`重整转增`保留在原始表中，但不自动视为全部无偿分给原股东；对应价格断点进入因子兜底。

`adjustment_factor_events`由本地 `close_adj / close_raw` 的变化推导，共3,393行。`validation_status`含义如下：

| 状态 | 含义 | 回测处理 |
|---|---|---|
| `matched` | 公告账本收益与前复权收益差异不超过0.2% | 现金和股数按公告入账 |
| `review` | 差异大于0.2%且不超过1% | 仍按公告入账，同时保留复核标记 |
| `factor_only` | 无法由普通分红公告解释 | 使用复权比例作为合成股数乘数 |
| `mismatch` | 差异超过1% | 阻止回测，必须人工处理 |

对除权日 (t) 和该证券上一行情日 (t-1)，分类公式为：

```text
F_t = close_adj_t / close_raw_t
factor_ratio = F_t / F_(t-1)
adjusted_return = close_adj_t / close_adj_(t-1) - 1
share_multiplier = 1 + (每10股送股 + 每10股转增) / 10
ledger_gross_return = (close_raw_t × share_multiplier + 每股税前现金) / close_raw_(t-1) - 1
return_residual = ledger_gross_return - adjusted_return
```

分类使用 `ABS(return_residual)`。`matched`不超过0.002，`review`大于0.002且不超过0.01，`mismatch`大于0.01；没有可用于股东记账的普通公告时为`factor_only`。日期严格使用该证券本地行情的相邻两行，不把周末或停牌期间机械视为一个交易日。

手工复核示例：`600519`在2024-06-19为每股税前现金30.876元、股数乘数1；`002594`在2025-07-29为每股税前现金3.974元、股数乘数3；`600515`在2021-12-22属于重整事件，使用 `factor_ratio=1.477002` 的合成股数兜底，不把公告中的全部重整转增直接分给原股东。

`corporate_action_download_status`为每只证券保存`success`、`success_fallback`或`empty_fallback`等状态。正式库不允许保留`failed`。

### 6.10.2 `daily_security_status`

每日历史ST与交易状态表，主键为 `(date, stock_code)`。

| 字段 | 说明 |
|---|---|
| `is_st` | Baostock历史ST标志，0或1 |
| `trade_status` | 独立重取的交易状态，用于和行情表核对 |
| `source` | 当前为`baostock` |
| `downloaded_at` | 批量抓取时间 |

正式验收要求它与 `daily_price_raw` 行数和主键集合完全相同，且 `trade_status` 冲突为0。归档位于 `data_v5/security_status/`，离线导入时校验SHA-256。

### 6.10.3 `security_transitions`

跨证券代码结算表，主键为 `(source_stock_code, event_date)`。`record_date`是源证券换股登记日，`event_date`是目标新增股份上市并在账户显示的日期，`exchange_ratio`表示每一股源证券换得的目标证券股数。`implementation_announcement_url`、`result_announcement_url`以及两个公告镜像`art_code`用于审计来源；`verification_status`必须为`official_sse_verified`，否则正式回测和数据库验收都会停止。

### 6.11 `daily_universe` 视图

回测首选入口。它按交易日连接：

- `trading_calendar`；
- `universe_membership`；
- 原始行情；
- 前复权行情；
- 最近一次有效的调仓快照权重；当前全部为空。

当前版本中，每个覆盖范围内的交易日严格返回300行。停牌或退市后无源行情的股票仍保留成员身份，但 `is_tradeable=0`，价格可以为 `NULL`。因为临时调整日期被省略，当前133个无行情成员日集中在 `600837` 和 `601989`，分别持续到下一次半年定期调整。

视图主要字段：

| 字段 | 可空 | 说明 |

### 9.10 计算前复权日收益率

```sql
WITH calendar_order AS (
    SELECT
        date,
        LAG(date) OVER (ORDER BY date) AS previous_market_date
    FROM trading_calendar
    WHERE is_trading_day = 1
),
prices AS (
    SELECT
        date,
        stock_code,
        close_adj,
        LAG(close_adj) OVER (
            PARTITION BY stock_code
            ORDER BY date
        ) AS previous_close_adj,
        LAG(date) OVER (
            PARTITION BY stock_code
            ORDER BY date
        ) AS previous_price_date
    FROM daily_price_adjusted
),
daily_returns AS (
    SELECT
        p.date,
        p.stock_code,
        p.close_adj,
        CASE
            WHEN p.previous_price_date = c.previous_market_date
            THEN p.close_adj / p.previous_close_adj - 1.0
            ELSE NULL
        END AS daily_return
    FROM prices AS p
    JOIN calendar_order AS c ON c.date = p.date
)
SELECT
    u.date,
    u.stock_code,
    r.close_adj,
    r.daily_return
FROM daily_universe AS u
LEFT JOIN daily_returns AS r
  ON r.date = u.date
 AND r.stock_code = u.stock_code
ORDER BY u.date, u.stock_code;
```

收益率先在完整 `daily_price_adjusted` 上计算，再连接当日股票池。只有上一价格日期等于市场前一交易日时才输出日收益率；停牌、缺行情或股票离池后重新入池不会被误算成单日收益。不要用 `close_raw` 直接跨除权日计算收益率。

### 9.11 计算20个有效观测的移动平均

```sql
WITH windows AS (
    SELECT
        date,
        stock_code,
        close_adj,
        COUNT(close_adj) OVER (
            PARTITION BY stock_code
            ORDER BY date
            ROWS BETWEEN 19 PRECEDING AND CURRENT ROW
        ) AS observation_count,
        AVG(close_adj) OVER (
            PARTITION BY stock_code
            ORDER BY date
            ROWS BETWEEN 19 PRECEDING AND CURRENT ROW
        ) AS average_close
    FROM daily_price_adjusted
)
SELECT
    date,
    stock_code,
    close_adj,
    CASE WHEN observation_count = 20 THEN average_close END AS ma20
FROM windows
ORDER BY stock_code, date;
```

该查询要求20个非空价格观测后才输出 `ma20`。如果策略严格要求连续20个市场交易日，还需要像第9.10节一样比较窗口内价格日期与 `trading_calendar`，缺失任何交易日时将指标设为 `NULL`。

```sql
        close_adj,
        CASE WHEN observation_count = 20 THEN average_close END AS ma20
    FROM windows
)
SELECT
    u.date,
    u.stock_code,
    u.is_tradeable,
    i.close_adj,
    i.ma20
FROM daily_universe AS u
LEFT JOIN indicators AS i
  ON i.date = u.date
 AND i.stock_code = u.stock_code
WHERE u.date = '2023-12-11'
ORDER BY u.stock_code;
```

这是更推荐的回测模式：先用完整个股历史计算指标，再用当日历史股票池过滤。

## 10. 回测使用规则

### 10.1 推荐数据路径

1. 从 `daily_price_adjusted` 计算指标和收益率；
2. 用 `daily_universe` 过滤当前版本推导的当日成分股；
3. 用 `is_tradeable` 判断能否成交；
4. 用原始OHLC模拟开盘、收盘、止损和滑点；
5. 用 `corporate_action_daily`增加税前现金分红和送转股数；
6. 对 `factor_only` 事件使用复权因子合成持股兜底；
7. 用 `security_transitions`在新增股份上市日结算跨代码吸收合并；
8. 用 `data_quality_issues` 排除阻断问题或记录研究限制。

### 10.2 防止未来函数

- 不使用未来日期的成分股名单；
- 不使用 `bfill`；
- 不把停牌日价格当成可成交价格；
- 调仓信号和实际成交时间必须在回测规则中明确；
- 官方公告日期与生效日期不应混用；
- 使用调仓后生效名单时，成交时间至少应满足策略的信息可用性约束。

### 10.3 成交额和成交量

成交均价应基于不复权口径：

```sql
SELECT
    date,
    stock_code,
    amount_cny / volume_shares AS raw_vwap,
    low_raw,
    high_raw
FROM daily_price_raw
WHERE volume_shares > 0
  AND amount_cny > 0;
```

不要使用 `amount_cny / volume_shares` 与 `close_adj` 比较。

### 12.3 覆盖、续传和失败规则

- `csi300_download_v5.py --overwrite` 会重新下载当前成分股文件；
- `download_membership_prices.py` 按代码跳过已存在历史文件；
- 网络任务中断后可以重复运行，原子写入可避免半截CSV；
- manifest中的失败项必须为0，或在质量报告中有明确阻断记录；
- 不能通过删除membership中的缺失股票来让校验通过；
- DataGrip必须断开正式SQLite连接，避免Windows文件锁阻止原子替换；
- 正式构建前应备份CSV、快照、官方公告证据和旧SQLite。

续跑检查点如下：

| 命令 | 成功检查点 | 重跑行为 | 建议恢复方式 |
|---|---|---|---|
| `csi300_download_v5.py` | `manifest.json` | 使用`--overwrite`会重下已有当前成分文件 | 断点续跑时去掉`--overwrite` |
| `download_hs300_membership_snapshots.py` | `membership_snapshots.csv` | 覆盖目标快照 | 仅在确需刷新快照时重跑 |
| `download_membership_prices.py` | `historical_price_manifest.json` | 按代码跳过已有成对文件 | 修复校验失败文件后重跑 |
| `build_csi300_sqlite.py` | 新SQLite和`database_manifest.json` | 原子替换数据库，并清除旧公司行为完成状态 | 随后立即执行公司行为离线导入或联网构建 |
| `apply_official_membership.py` | 官方更新报告和备份 | 事务更新成分表 | 输入不变时可安全重跑，但无需重复 |
| `build_corporate_actions.py` | 每只证券的下载状态 | 跳过`success`和回退成功/空状态 | 直接重跑相同命令 |
| `build_security_status.py` | 与原始行情逐键一致的状态表和SHA-256清单 | 默认全量刷新状态表 | 数据库重建后优先用`--import-dir`离线恢复 |

只强制重试一只公司行为证券时，先在DataGrip事务中删除该证券的状态和旧明细，再运行普通构建命令；其他492只会被跳过：

```sql
BEGIN;
DELETE FROM corporate_actions WHERE stock_code = '600837';
DELETE FROM corporate_action_download_status WHERE stock_code = '600837';
COMMIT;
```

不要使用 `--refresh` 重试单只证券；该选项会刷新全部证券。

### 12.4 当前可重复性的边界

现有脚本能够从固定CSV确定性重建SQLite，但从网络重下载不保证逐字节一致，原因包括供应商历史修订、前复权重算、成分接口更新和依赖版本变化。正式版本还应增加：

- 为 `requirements-research.txt` 记录发布版本和SHA-256；
- 每个输入文件的SHA-256；
- 官方公告原件及其校验和；
- 公司行为归档的逐文件SHA-256；当前已经保存调整事件和抓取时间；
- 数据版本号和 `as_of_date`。

### 12.5 日常增量维护

全量重建用于建立基线库；基线完成后，日常维护统一使用：

```powershell
python update_csi300_incremental.py --full-validate
```

该命令从数据库最大交易日开始检测新增交易日，更新库中全部历史证券及新观察到的成分证券，同时补充原始行情、前复权行情、历史ST状态、沪深300价格基准和Baostock完整成分观测。运行前可先检查而不修改数据库：

```powershell
python update_csi300_incremental.py --dry-run
```

如需更新到指定日期：

```powershell
python update_csi300_incremental.py --end-date 2026-08-11 --full-validate
```

每次网络返回保存在`data_v5/increments/<run_id>/`。目录内为未压缩CSV及`manifest.json`，清单记录每个文件的行数和SHA-256。SQLite是日常增量主库；原有493组CSV是基线归档，不再每天重写。

前复权数据不能简单逐日拼接。更新器读取10个重叠交易日：若供应商的新旧前复权价格只相差固定比例，则统一重标定更早历史；若比例不是常数，则全量刷新该证券前复权历史。所有处理写入`price_revision_audit`。

离线重放命令：

```powershell
python update_csi300_incremental.py --replay-dir data_v5/increments
```

重放前会校验CSV行数和SHA-256；已应用的`run_id`会直接跳过，因此命令可以安全重跑。

DataGrip可以在更新时保持只读连接。若Query Console存在尚未提交的写事务，增量程序会等待最多30秒后明确报锁库错误，不会产生部分提交。

## 13. 官方公告核验流程

当前官方输入为项目所有者从中证指数官网人工整理并确认可靠的 `CSI300_remake_report.xlsx`，覆盖2019年12月至2026年6月的14次半年定期调整，共247组调入调出。该文件只覆盖定期调整，不覆盖临时调整。

`apply_official_membership.py` 执行以下校验：

1. 检查Excel五个核心字段、代码格式、空值和重复项；
2. 检查每期调入数等于调出数；
3. 将每期调入调出集合与Baostock相邻完整快照做精确集合匹配；
4. 2019年至2020年使用表内已经表示“第二个星期五后首个交易日”的正式生效日期；
5. 2021年起将收市后实施日期映射到下一个交易日；
6. 取匹配后的完整300股集合生成14期正式快照；
7. 保留全部20期原始Baostock观测快照和Excel SHA-256；
8. 重建成员有效区间并确认每天严格300只；
9. 在全部检查通过后提交事务，否则回滚；
10. 生成修正前后差异报告和数据库备份。

未来调整时只需把新一期官网公告追加到同一Excel。日常增量程序会保存每次不同的Baostock完整300只集合；只有Excel事件与相邻观测快照的调入调出集合完全匹配后，正式股票池才会切换。

Excel事件已经存在、但新集合尚未被观察到时，状态为`pending_official_adjustment`；Baostock集合已经变化、但Excel没有相应事件时，状态为`observed_change_unconfirmed`。这两种状态都继续更新行情，冻结`universe_membership`，并增加`unverified_component_change`警告。

当前元数据口径：

```text
membership_officially_verified = True
membership_scope = official_regular_adjustments_only
temporary_adjustments_included = False
membership_valid_from_semantics = first_trading_day_new_pool_is_usable
```

这里的“官方核验”仅指半年定期调整。研究报告不能省略 `temporary_adjustments_included=False`。如果未来补齐临时公告，应在新的数据版本中导入临时事件并重新生成区间，不能直接删除现有审计记录。

## 14. 质量警告说明

当前143条警告包括：

| 类型 | 数量 | 处理方式 |

| `vwap_outside_ohlc` | 5 | 保留原始值，必要时用第二数据源核查 |

## 17. 常见问题

### 17.1 为什么不是每天直接存一个300股CSV？

规范化存储可以避免重复行情，保留成分区间和原始来源，并通过 `daily_universe` 视图随时生成每日300股结果。

### 17.2 当前300只股票还有用吗？

有用。它们是493只历史成分股全集的一部分，也用于核对最新快照。但不能单独回溯到2020年。

### 17.3 为什么停牌股票仍出现在 `daily_universe`？

成员身份和可交易状态是不同概念。停牌股票仍属于指数，但不能成交。

### 17.4 为什么不填补133个缺价成员日？

填补估值价格不等于存在可成交价格。当前数据库保留 `NULL` 并设置 `is_tradeable=0`。这133行仅涉及临时调整日期未纳入正式区间的`600837`和`601989`，避免制造虚假成交。

### 17.5 为什么权重全是空？

免费Baostock历史成分快照不提供调仓权重。必须从中证公告、Tushare Pro、Wind或其他专业来源补充。

### 17.6 可以直接用于正式研究吗？

可以用于半年定期调整口径的研究和回测开发。它不是包含临时调整的官方逐日完整成分库；发表或资金决策前必须披露临时调整省略，并根据策略决定是否需要历史权重、调整因子和第二行情源复核。

### 17.7 数据库可以直接修改吗？

不推荐。正式库应由原始行情和成分快照、官方Excel、公司行为CSV归档、`apply_official_membership.py`、`build_corporate_actions.py`及`build_security_transitions.py`重建。手工修改数据库会破坏可追溯性；第12.3节的单证券下载状态重置是有明确恢复命令的维护例外。

### 17.8 公司行为已经完全等同于实盘了吗？

没有。当前普通分红送转使用公告经济条款，解决了不复权价格直接估值的主要断层；但现金按税前金额在除权日确认，没有模拟个人持有期限红利税、派息到账日和送转股份可卖日期。17个特殊事件使用合成股数兜底，仅适合研究净值连续性，不是券商交收流水。两笔吸收合并已按官方比例和上市日跨代码结算，但零碎股只能做最多一股误差的近似。

## 18. 最终验收清单

每次正式使用前确认：
