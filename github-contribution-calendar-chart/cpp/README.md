# 本地 Git 提交热力图 C++ 单体版

这是一个面向 Windows 的本地 Git 提交统计软件。程序使用 Win32 API 和 GDI+ 绘制界面，不启动 Node.js 服务，不开放局域网端口，也不依赖 WebView。发布时只需要携带一个 `heatmap.exe`。

## 构建

要求：Windows 10 或更高版本，以及 Visual Studio 2022 C++ Build Tools（包含 x64 工具链和 Windows SDK）。

在项目根目录运行：

```powershell
.\cpp\build.ps1
```

构建脚本会自动定位 MSVC 环境，使用 `/MT` 静态链接 CRT，输出：

```text
cpp\build\heatmap.exe
```

程序是纯原生窗口应用，双击即可运行。也可以将桌面快捷方式的目标直接指向该 exe；启动后会打开本地原生窗口，不需要额外的服务进程。

## 数据与配置

运行数据默认保存到：

```text
%LOCALAPPDATA%\LocalGitHeatmap\
├── config.json       扫描范围、作者筛选等配置
├── index.json        仓库索引、指纹和时间戳
└── repositories\    每个仓库独立的提交日统计 JSON
```

首次启动会将项目根目录的旧 `config.json` 和 `data\` 缓存迁移到上述目录。JSON 文件采用临时文件加替换的原子写入方式，程序异常退出时不会直接覆盖上一份完整缓存。备份整个 `LocalGitHeatmap` 目录即可迁移数据；删除该目录会触发下一次全量初始化。

## 扫描和增量刷新

- 启动时先加载本地 JSON，已有历史会立即显示，随后后台检查仓库。
- 固定磁盘和可移动磁盘都会被发现；跳过系统目录、隐藏目录和常见依赖目录，并按最大深度限制搜索。
- 仓库索引保存 refs 指纹。点击刷新（`F5`）时，只有指纹变化、新发现或缓存缺失的仓库才重新读取 Git 历史；未变化的仓库只更新时间戳。
- 首次扫描需要遍历 Git 历史，耗时取决于磁盘和仓库数量。日常刷新通常只执行 refs 检查，已有数据不变时不会重复统计历史。
- Git 命令通过 Windows 管道执行，不经过 shell 临时文件。扫描和统计在后台线程完成，界面保持响应。

## 界面操作

- `F5`：刷新仓库和提交数据
- `F6`：重新发现磁盘中的 Git 仓库
- `Ctrl+D`：切换深色/浅色主题
- 搜索框：按仓库名称或路径筛选
- 左侧复选框：选择参与热力图统计的仓库
- 年份按钮：切换年度视图
- 仓库右键菜单：在资源管理器中打开目录
- `Esc`：清空搜索框或关闭当前交互状态

顶部状态栏会显示当前操作、仓库数量、最近一次刷新时间和错误提示。窗口支持单实例运行，再次启动只会唤醒已有窗口。

## 源码结构

```text
cpp/src/
├── entry.cpp       WinMain、单实例和诊断入口
├── state.cpp       配置、缓存、后台扫描和贡献数据状态
├── cache_store.*   JSON 索引/仓库数据的加载、迁移和原子保存
├── git_scan.*      全盘发现、refs 指纹和 Git 历史统计
├── ui_draw.*       GDI+ 双缓冲绘制
├── ui_control.cpp  Win32 消息、快捷键和交互
├── json.*           轻量 JSON 解析/序列化
└── platform.*      UTF-8 文件、路径和 Windows 平台工具
```

## 诊断

```powershell
.\cpp\build\heatmap.exe --diagnose
```

诊断模式会检查 JSON、UTF-8 原子文件、Git 可用性和旧缓存兼容性，退出码为 `0` 表示通过。

## 与 Web 版的边界

Web 版仍可用来开发和回归 UI；C++ 版是独立的本地查看器。两者共用作者筛选和仓库发现的配置语义，但运行时数据目录彼此独立，C++ 版不会启动 HTTP 服务，也不会占用 Web 服务器端口。
